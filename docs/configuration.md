# Configuration

`createCacheTagsExtension(redisAdapter, config)` requires the generated
descriptor and a scope declaration for each cacheable model:

```ts
import { cacheSchema } from './generated/cache-tags';

const config = {
    schema: cacheSchema,
    models: {
        WorkOrder: {
            tenant: { field: 'organizationId', namespace: 'organization' },
        },
        Equipment: {
            tenant: { field: 'organizationId', namespace: 'organization' },
        },
        AuditEvent: { tenant: false },
    },
};
```

Run `prisma generate` whenever the Prisma schema changes. The descriptor is
generated by:

```prisma
generator cacheTags {
  provider = "prisma-cache-tags-generator"
  output   = "./generated/cache-tags"
}
```

## `CacheTagsConfig`

| Name                | Type                    | Default                | What it does                                                                                       |
| ------------------- | ----------------------- | ---------------------- | -------------------------------------------------------------------------------------------------- |
| `schema`            | `CacheSchemaDescriptor` | required               | Generated model, relation, scalar, primary-key, and unique-key metadata.                           |
| `models`            | `CacheModelConfigs`     | required               | Declares `{ tenant: { field, namespace } }` or `{ tenant: false }` per model.                      |
| `enabled`           | `boolean`               | `true`                 | Disables caching while still running Prisma normally.                                              |
| `defaultTtlSeconds` | `number`                | `30`                   | TTL when a read does not provide one.                                                              |
| `maxTtlSeconds`     | `number`                | `300`                  | Upper bound for read TTLs and tag-version retention.                                               |
| `keyPrefix`         | `string`                | `'prismaCacheTags:v3'` | Prefix for query, tag-version, and lock keys. Earlier-version entries are ignored.                 |
| `cacheNull`         | `boolean`               | `true`                 | Allows `null` results to be cached.                                                                |
| `cacheEmpty`        | `boolean`               | `true`                 | Allows empty arrays to be cached.                                                                  |
| `schemaVersion`     | `number`                | `1`                    | Application cache-shape version; bump it to invalidate all entries.                                |
| `maxTagsPerQuery`   | `number`                | `30`                   | Maximum complete read subscription size. Over-limit reads bypass; write publications are uncapped. |
| `stampede`          | `CacheStampedeOptions`  | see below              | Distributed single-flight settings.                                                                |
| `logger`            | `Logger`                | no-op                  | Receives bounded diagnostics and bypass warnings.                                                  |
| `metrics`           | `Metrics`               | no-op                  | Receives hit, miss, bypass, and script events.                                                     |

Every tenant-scoped model must have a scalar configured tenant field in the
generated descriptor. A shared namespace is an explicit application invariant:
related rows in that namespace must carry the same tenant identity. Different
namespaces require independently proven scope or the read bypasses.

## Read dependencies

Relations referenced by `select`, `include`, relation filters (`is`, `isNot`,
`some`, `every`, `none`), relation-aware ordering, `_count`, and nested relation
arguments are inferred automatically. Scalar IDs, computed values, and
external data are not relations; provide a resolver:

```ts
const models = {
    WorkOrder: {
        tenant: { field: 'organizationId', namespace: 'organization' },
        readDependencies: ({ model, operation, args, scopes, schema }) => [
            { model: 'ExternalEquipment', scope: scopes[0] },
            { tag: `dashboard:${model}:${operation}` },
        ],
    },
    ExternalEquipment: { tenant: false },
};
```

The resolver receives `{ model, operation, args, scopes, schema }` and returns
`{ model, scope }` or `{ tag }`. Results merge with inferred dependencies by
default. `cache.mergeTags: false` replaces the complete inferred set, so the
caller owns correctness for every model, scope, root fallback, and explicit
tag needed by the read.

## `CacheReadOptions`

Caching is opt-in for `findUnique`, `findFirst`, `findMany`, `count`, `aggregate`,
and `groupBy`.

| Name         | Type                   | Default             | What it does                                                                            |
| ------------ | ---------------------- | ------------------- | --------------------------------------------------------------------------------------- |
| `ttlSeconds` | `number`               | `defaultTtlSeconds` | Requested TTL, clamped to configured bounds.                                            |
| `key`        | `string`               | generated           | Adds a component without replacing model, operation, arguments, scope, or dependencies. |
| `enabled`    | `boolean`              | `true`              | Bypasses cache for this read when false.                                                |
| `debug`      | `boolean`              | `false`             | Emits bounded hit/miss/population diagnostics.                                          |
| `tags`       | `string[]`             | `[]`                | Adds explicit application tags.                                                         |
| `mergeTags`  | `boolean`              | `true`              | Merges explicit tags with inferred subscriptions; false replaces them.                  |
| `stampede`   | `CacheStampedeOptions` | `config.stampede`   | Overrides single-flight settings.                                                       |

Reads subscribe to their primary and dependency model tags, the resolved
tenant root, and global model fallbacks. The root is an explicit full-scope
invalidation target; global fallbacks make unresolved writes safe.

## `CacheWriteOptions`

Writes execute first. After success, the extension publishes changed model and
proven entity tags plus explicit `tags`; it does not cache the write result.
Normal tenant-resolved writes do not publish tenant roots or global model
fallbacks. A tenant-unresolved primary or nested write publishes the global
model fallback and warns. Nested writes use only explicit arguments or returned
rows as tenant evidence.

| Name        | Type       | Default | What it does                                                                                              |
| ----------- | ---------- | ------- | --------------------------------------------------------------------------------------------------------- |
| `tags`      | `string[]` | `[]`    | Adds application publication tags.                                                                        |
| `debug`     | `boolean`  | `false` | Emits bounded publication diagnostics.                                                                    |
| `mergeTags` | `boolean`  | `true`  | Merges explicit tags with inferred publications; false makes the caller responsible for all invalidation. |

## Invalidation and transactions

```ts
import { invalidateScope } from 'prisma-extension-cache-tags';

await invalidateScope({ namespace: 'organization', id: 'org_1' }, redisAdapter, config);
```

`invalidateScope` bumps only the tenant root, intentionally invalidating every
read subscribed to that scope. Cross-namespace reads without proof bypass
caching. Reads whose complete subscriptions exceed `maxTagsPerQuery` also
bypass; correctness tags are never silently truncated. Publications remain
uncapped.

Writes inside callback or batch `$transaction` forms accumulate unique
publications and flush once after commit. Rollback publishes nothing. Use
`withCacheInvalidation` only when an intercepted transaction callback is not
available; it does not replace database transaction semantics.

## `CacheStampedeOptions`

| Name        | Type     | Default | What it does                                      |
| ----------- | -------- | ------- | ------------------------------------------------- |
| `waitMs`    | `number` | `1500`  | Maximum waiter polling time.                      |
| `pollMs`    | `number` | `50`    | Poll interval.                                    |
| `lockTtlMs` | `number` | `5000`  | Lock lifetime; set above expected query duration. |

## Observability

`onCacheEvent` reports `{ model, operation, result, path, reason? }`, where
`result` is `hit`, `miss`, or `bypass`; bypass reasons are bounded values such as
`tenant-scope-missing`, `cross-namespace-scope-unknown`, and
`dependency-tag-limit`. Diagnostics do not include complete arguments, tenant
IDs, returned rows, or tag strings as metric dimensions.
